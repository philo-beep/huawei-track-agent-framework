# 数据集工作区说明

## 负责人

D 数据与知识库工程师负责数据、清洗、切片、入库准备和质量；A 负责检索代码消费和验收，B 负责入库接口边界。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `raw/` | 原始证据、官网快照、固定清单和候选附件 |
| `cleaned/` | 可追溯的本地知识索引和清洗结果 |
| `test_sample/` | 仅用于测试的合成样例和示例输出 |
| `ima/` | IMA 只读抓取记录、已验证快照、目标产品 EvidenceBundle 和图片清单 |

2. 阅读 `../README.md` 和 `../agent_spec/README.md`。

## 数据规则

- 每条关键事实保留来源库、具体条目、内容指纹、抓取时间和适用型号/SKU。
- 官网失败项保留失败状态，不补空价格或伪造成功。
- 原始资料、清洗索引和测试样例分开存放。
- 不加入真实客户隐私、凭据、日志、原始 ZIP 或模型权重。
- 图片候选不等于正式配图；未核验时保持 `model_verified=false`。
- 价格必须区分公开参考价、历史快照、起售价、补贴估算和可成交报价。

## 验证与交接

交付附数据计数、来源清单、清洗命令、测试结果、失败项和待核实项。A、B、C 或 E 发现问题时提交给 D 评估数据修正，A 复验检索链路，E 协助验收。



## IMA 证据区

`ima/` 保存官方 IMA Skill 的离线可复验产物：

- `captures/`：真实请求中实际观察到的请求 ID、错误码、哈希、摘录和本地镜像对应关系。
- `ima-evidence-bundle.json`：能力与抓取状态总账，明确区分“代码已实现”“真实调用已验证”“完整覆盖已达成”。
- `targets/<产品>/evidence-bundle.json`：符合运行区 `EvidenceBundle v1.0` 扩展契约的目标产品证据。
- `targets/<产品>/image-manifest.json`：图片候选、内容 SHA-256、存放路径、适用型号和核验状态。
- `targets/<产品>/sources/`：经过 SHA-256 校验的正文或明确标记为 verified-excerpt 的摘录。
