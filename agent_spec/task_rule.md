# 数据与规范任务规则

## 1. 适用范围

本规则用于数据区内的采集、清洗、索引、样例维护、规范更新和文档交付。业务运行逻辑不在此实现。

## 2. 标准流程

### 第一步：任务登记

- 明确任务目标、允许修改目录、输入、交付物、验收条件和停止点。
- 在 `docs/issue_record.md` 查重，避免重复处理同一缺口。
- 涉及价格、图片、客户样本或外部凭证时，先确认证据边界，不以默认值代替事实。

### 第二步：来源采集

- 本地知识库优先，产品参数和价格优先华为官网 / 华为商城。
- 原始证据存入 `datasets/raw/`；文件名采用稳定 ID 或内容指纹，避免同名覆盖。
- 采集清单至少记录：ID、来源类型、URL、抓取时间、HTTP 状态、内容指纹、本地路径、限制。
- 失败条目保留 `failed`、错误信息和重试记录；路径与价格必须为空。

### 第三步：清洗与索引

- 清洗结果写入 `datasets/cleaned/local_kb_index.json`。
- 文档保留原条目、内容指纹、知识库别名和原文位置。
- 候选图路径统一为 `datasets/raw/assets/<sha256>.<ext>`。
- 价格记录保留原始字段、来源条目、核验状态和 `is_current_transaction_quote`。
- 去重只合并字节或内容确实相同的记录；保留来源别名，不把同一来源算作两个独立佐证。

### 第四步：价格核验

1. 确认产品型号与精确 SKU。
2. 确认配置、数量、地区、用户类型、活动条件、有效期和库存。
3. 记录页面金额、参考金额、币种、单位、获取时间和页面 URL。
4. 判断记录属于历史快照、公开参考、搭配价、起售价还是可成交报价。
5. 无法闭环时保持正式报价为空，并在问题记录中写明所缺字段。

四级假设模型必须单独存放并标记「基于行业惯例与赛题推断，待官方确认」，不得写入官方价格表。

### 第五步：图片登记

- 候选图记录附件路径、原条目、原始 URL、产品名、描述和关联方式。
- 默认 `model_verified=false`、`usable_as_verified_product_image=false`。
- 只有完成画面、型号、配色、SKU、版权与页面归属核验后，才可由有权角色更新状态。
- 不得因图片位于某产品目录就直接认定它是该产品正式配图。

### 第六步：测试样例

- 合成样例放 `datasets/test_sample/`；运行契约用例可由运行区 `tests/` 维护。
- 每个样例标注 `synthetic=true`、覆盖目标、输入和预期边界。
- 至少覆盖新客/老客、大客户/小客户、行业差异、首次咨询、比价、续约、加购、预算不明、信息极少、规则冲突、极端预算和平台差异。
- 不得把合成结果写成真实咨询或成交证明。

### 第七步：规范与文档

- 规则变化先更新 `AGENTS.md` / `task_rule.md` / `constraint.md`，再更新验收和问题记录。
- 赛事需求变化写入 `docs/赛事需求文档.md`，注明来源和生效日期。
- 每次有效改动写入 `docs/变更日志.md`，记录改了什么、如何验证、哪些尚未完成。

### 第八步：验收

- 按 `acceptance.md` 逐项检查，不跳项。
- 运行必要回归；记录命令、环境、通过数、跳过数、失败数。
- 检查旧路径、重复文件、错误层级、空路径、伪造价格和未标注样例。
- 不通过项退回原责任角色；A 负责 Agent 和验收脚本修复，E 协助记录与复验，不代为修改业务内容。

### 第九步：交付

交付消息必须包含：

- 任务 ID 与改动目录；
- 文件清单和数据计数；
- 来源与证据位置；
- 验证结果；
- 未完成项及状态；
- 是否需要外部条件；
- 是否已提交或部署（默认否，除非有独立证据）。

## 3. 命名与格式

- 目录和稳定 ID 使用小写英文、数字、连字符或明确中文文档名。
- JSON 使用 UTF-8、有效 JSON，不写注释和尾逗号。
- Markdown 使用 UTF-8，标题层级清晰，命令使用代码块。
- 时间统一记录时区；官网抓取优先 ISO 8601。
- 文件指纹优先 SHA-256；不得用文件大小替代内容指纹。

## 4. 失败与阻塞

- 单条采集失败不影响其他条目，但必须记录并保持空字段。
- 外部凭证、价格政策、客户验证或赛事许可缺失时，标记 `pending_external`。
- 不用伪造、估算或历史数据关闭阻塞；可以先完成其他独立工作。
- 连续重复失败先查根因，再决定重试；不得无限循环重试。

## 5. 禁止事项

- 不在数据区新增业务代码或运行服务。
- 不导入其他模块内部源码来绕过公共契约。
- 不复制原始知识库 ZIP、客户隐私、日志、凭据或模型权重。
- 不删除失败记录、不修改评分来制造通过。
- 不把 `draft`、`pending_external` 或本地测试结果写成已发布、已验证业务效果。
