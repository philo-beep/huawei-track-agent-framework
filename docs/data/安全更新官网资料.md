# 安全更新官网资料

`data/import_official.py` 是离线规格证据包验证器和导入器。它不联网、不调用IMA或魔搭，也不执行采集脚本。默认只验证；只有明确传入 `--apply` 才更新活动清单。

首版仅接受既有受审白名单的两条规格页：

| id | 完整型号 | url与final_url必须精确相同 |
| --- | --- | --- |
| `matebook-14-2024-specs` | `HUAWEI MateBook 14 2024` | `https://consumer.huawei.com/cn/laptops/matebook-14-2024/specs/` |
| `matebook-14-harmonyos-specs` | `HUAWEI MateBook 14 鸿蒙版` | `https://consumer.huawei.com/cn/harmonyos-computer/matebook-14-harmonyos-version/specs/` |

不接收商城价格、SKU、报价配置或图片。拒绝未知SKU只是防止误用，并不表示已经取得真实四级价格政策。现有演示报价和真实报价边界不变。

## 证据包与运行

证据包是操作者在获授权范围内取得的本地文件夹，不是URL；包含 `manifest.json` 及其引用的raw HTML、text UTF-8文件。包内路径均为相对包根目录的POSIX路径，不能含盘符、反斜线、空路径段、`.`、`..`、符号链接或Windows重解析点。

manifest最小外层结构如下，`entries`放实际证据条目，示例不提供任何真实授权或抓取记录：

```json
{
  "authorization": {
    "declared_authorized": true,
    "scope": "local_reference",
    "provided_by": "实际负责人的名称或受控代号",
    "reference": "授权文件或许可依据的可追溯标识"
  },
  "entries": []
}
```

空entries会被拒绝，实际需要1至2条规格证据。授权字段只是操作者声明，不是独立权利审核、网站真实性证明或商业发布许可。应由获授权负责人核对文件取得方式、用途及范围；网站可访问不能自动视为允许采集或再分发。

每条entry沿用 `data/official/manifest.json` 既有格式，至少具备：`id/source_type/url/final_url/product/title/fetch_status/http_status/model_identity_verified/fetched_at/raw_path/raw_sha256/text_path/text_sha256/text/fields`。必须显式 `sku=null/configuration={}/price=null/starting_price=null/images=[]/is_current_transaction_quote=false`。

`fields`不能空，保存 `name/value/unit/excerpt/scope/sku/configuration/source_pointer`；scope仅支持model，sku必须null、configuration必须空对象。`source_pointer.path`指向同entry的text路径，`sha256`相同，`start/end`为Python/Unicode码点定位，不是字节偏移。必须完整定位原文标签、值、相邻脚注及下一受审字段边界。

```powershell
python data/import_official.py --package "C:\本地授权证据包"
python data/import_official.py --package "C:\本地授权证据包" --apply
```

可用 `--workspace` 指定隔离工作区进行测试。工作区须已有 `data/official/manifest.json` 和现有 `backend/marketing/official.js`、`support.js`，不能把空目录误作活动数据集。依赖Python3.11+和Node.js；不需密钥，不会下载安装依赖。stdout成功返回单个JSON；拒绝写stderr JSON并以退出码1结束。

## 校验与更新顺序

1. 先在内存读取包与原manifest；拒绝重复JSON键、非有限数字和无效结构。单文件最大8MiB，候选及合并证据总量最多64MiB。
2. URL、来源ID和完整代际型号精确匹配白名单。抓取必须成功、HTTP200；时间须带时区、日历日期有效、不晚于实际当前时间、不超过7天。导入不会重写或刷新 `fetched_at`。
3. 复算raw/text SHA256；以现有 `TextParser` 从原HTML独立重建正文，要求与text文件及entry.text逐字一致；原始title与现有 `verified_identity` 型号检查也须通过。
4. 规格值由本次字段原文解析：分辨率、GB内存选项、存储选项、CPU和系统均不固定为旧数值。解析只接受受审标签/格式；出现新格式、代际或未支持字段就拒绝，不能猜测。原文受审脚注不可截断。哈希只能证明包内一致，不能独立证明离线文件确实由官网签发。
5. 候选与旧成功条目同型号同字段值或单位冲突时拒绝，包括同ID替换前旧值。合法的官网更新若与旧版冲突，也须先独立审核其代际/版本与替代关系，首版不会自动选择新值。
6. 合并保持其他旧记录不变，候选只替换对应ID；将合并后的全manifest及证据复制到系统隔离临时目录，调用**现有未修改的Node `loadOfficialReference`**复验。临时进程仅把读取根指向隔离目录，不改模块源码。字段/价格冲突、证据错误和候选型号未形成有效规格均拒绝；原有商城失败记录仍保留而不变造为成功。
7. 默认dry-run到此结束，清理临时目录，不创建活动目录的锁、备份、导入图或manifest。不会修改已有数据文件。
8. apply获得独占 `.import.lock`，再次核对原manifest字节未被其他进程改变；将新证据写入 `data/official/imported/<完整SHA256>.html或.txt`。已有相同路径只允许相同字节，绝不覆盖不同内容。
9. 原manifest逐字节备份到 `.collaboration/runtime/official-import-backups/<旧manifest-SHA256>.json`，仅供本机恢复，不公开。新manifest在同目录独占临时文件写完、flush/fsync后，再复核旧manifest未变化，最后 `os.replace` 原子切换。

同型号旧字段、现有文件哈希、Node业务校验、锁或写入失败均不切换活动manifest。apply写入中失败可能留下未被引用的不可变证据或旧版备份，但活动清单仍保持旧版。临时文件和本次持有的锁会在finally清理；已存在的其他进程锁不会被删除。并发保护适用于遵守同锁的导入器；不防御管理员在任意时刻主动绕过锁修改文件，不声称等同数据库事务或断电持久化保证。

## 范围与后续

7天是当前规格复核窗口，不是官网保证有效期。官方公开价格仍需另有完整SKU、资格、配置、时点和条件的授权证据；真实四级规则、库存交期与商业图片授权没有因此解决。现有价格一小时规则、真实金额null、图片未审核状态继续适用。

本工具不修改现有 `data/fetch_official.py`，也不能让旧采集脚本自动获得本工具的失败保留和原子更新能力。需要安全更新时应使用本工具，后续是否替换旧入口需单独审阅。导入后的 `safe_import.at` 是本地导入时间，`fetched_at`仍为来源抓取时间，两者不得混用。

公开候选只纳入审阅过的工具和说明。原始授权证据包、操作者声明详情、备份及未获转载许可的整页HTML/text不能因导入成功就自动发布。部署若需要新规格证据，应在E/QA确认数据使用和公开范围后另行更新白名单；此工具本身不执行Git或平台操作。
