# 协作框架范围与后续需求说明

本次产物是华为赛道项目的本地多 Agent 协作基础框架，依据用户提供的原始 `agent.md` 搭建。本文描述当前框架的使用者、能力和边界，不代表具体赛道产品已完成、模型已接入或项目已发布。

## 使用者与问题依据

当前框架面向本项目操作者和参与研发的成员，用于拆分工作、约定职责、交换交付、独立验收、追踪修复及准备发布候选。这里的协作问题直接来自 `agent.md` 的要求：多人分工不能越权，前后端应遵守同一契约，数据需要可追溯，问题需要准确退回责任人，任务与验收记录需要落盘，关键节点需要备份和一致性检查。这是已给定的项目协作需求，不是经过用户调研得出的市场结论。

真实赛道产品面向谁、解决什么现实痛点、包含哪些功能、是否需要训练模型，以及竞赛对华为技术栈、数据和平台的具体限制，均待确认。不能把框架的研发使用者直接当作赛道产品的最终用户，也不能以模拟案例填补需求证据。

## 使用流程

操作者先以 `templates/user-requirement.md` 明确业务需求与验收依据。主控建立带 owner、依赖和标准的任务，加载相应角色提示词，并按宿主实际并发能力分批指派。成员通过运行器提交开始、交付及修复消息；QA 按标准验收、退回责任人并复验。任务状态保存在本地，`status` 表示目标任务状态，不表示消息已经送达某个模型实例。

已验收文件改变后，由 QA reject 原任务，责任人 fix/deliver 后重新验收；上游验收内容变化还需退回受影响的下游原任务复验。准备发布时，有效任务须为 done 或有原因的 cancelled，至少一个 E 产品说明任务经 QA 通过，再由 E 对同一候选做产品一致性签字并由主控执行 release-check。

## 当前边界与阻塞

运行器是本地状态和消息管理工具，不会自动调用模型或训练 Qwen，不锁定实际宿主模型名称；D 的 Qwen 职责是未来业务实现的分工。七份提示词不等于七个常驻进程，实际 Agent 实例需由支持该能力的宿主会话启动并遵守其并发限额。字段中的角色名不是远程身份认证，目录检查也不是操作系统级隔离。

运行器不会自动创建 GitHub 仓库、上传文件或部署魔搭。账号认证、仓库创建、内容推送、平台构建与线上验证是不同步骤，不能相互替代。主控维护的 `docs/platform-status.md` 是这些动态进度的统一来源。2026-10-18 曾因平台返回“未绑定阿里云账号”而无法新建创空间，这是历史尝试记录；后续已按用户指示找到并沿用其现有“销售助手”空间 `philosophia/promotion-agent`。同日较早观察到的 Gradio 6.29.1/Initialized 配置也已成为历史：后续实时 API 显示该空间为 Docker、免费 CPU，runtime 为 Running，已有基线的构建日志显示标准库服务启动。空间配置会变化，当前配置与运行结果须核对动态状态文档及实际平台证据，不能将 Gradio 可选适配当作当前生产入口。文件上传、构建成功和 Running 状态均不等于页面及健康检查已通过线上验收。凭据不写入本文或仓库，不以本地门禁通过推定线上可用。

“销售助手”是用户已有空间的名称，不代表销售业务产品已经交付。本阶段仅提供只读框架介绍、角色职责及模拟协作流程，不读取真实任务看板，不导入业务数据，不调用模型，也不训练或启动实际 Agent 实例。Docker 使用标准库展示服务，Gradio 仅保留为可选适配；两者的具体响应、启动方式和本地验收范围分别以实现说明和 QA 报告为准，不能把任一本地服务验收等同于当前平台入口的线上验证。

桌面写入限制是前一阶段的历史阻塞，2026-10-18 环境权限更新后已解决。主控已将源文件迁入用户指定的主要工作区 `C:\Users\pop\Desktop\华为项目`，共核对 47 个源文件，其中 46 个新增，原始 `agent.md` 保留且 hash 一致；框架的 24 项测试已在桌面工作区通过。临时目录 `C:\Users\pop\AppData\Local\Temp\huawei-framework` 是历史暂存位置，不再作为主要工作区。当前服务验收及测试证据以 `reviews/deployment-review.md` 和 `.collaboration/state.json` 为准；QA 已验收本地展示服务，完整 30 项测试通过。本地测试和验收不等于 Docker 构建、远端推送或线上部署验收。

本任务仅交付范围说明，QA 的实际验收状态以看板及评审记录为准，不代表完整框架候选已经完成 E 发布签字。训练效果、销售业务功能、线上运行和赛道产品验收都没有在本文中作完成声明。
