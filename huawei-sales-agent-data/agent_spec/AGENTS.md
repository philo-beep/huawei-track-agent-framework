# 华销智策数据区协作规则

本文件约束 `huawei-sales-agent-data/` 及其全部子目录。更深的 `AGENTS.md` 如存在，以更具体规则为准；用户当前指令优先于本文件。

## 1. 区域定位

- 本区只保存数据、合成样例、Agent 规范、赛事和项目文档。
- 本区不是运行区，不新增网页、Node/Python 业务代码、启动脚本、测试运行器或模型权重。
- 运行区位于 `../huawei-sales-agent/`。数据区可以记录运行契约和验收结果，但不能复制并维护第二套业务实现。
- 根目录只允许 `datasets/`、`agent_spec/`、`docs/`、`README.md`。

## 2. 责任边界

| 责任角色 | 可维护区域 | 主要职责 |
| --- | --- | --- |
| Agent 核心（A） | `agent_spec/` | Agent 规则、任务规范、约束和验收清单 |
| 数据与知识库（D） | `datasets/` | 原始证据、清洗索引、切片、样例数据、来源与质量说明 |
| 产品与答辩（E） | `docs/`；复核 `agent_spec/constraint.md`、`acceptance.md` | 赛事需求、问题记录、产品说明和材料一致性 |
| 接口（B） | 只读引用 | 审核字段与公共契约的一致性，不在本区另建契约副本 |
| 前端（C） | 只读引用 | 提供用户流程、展示边界和前端问题反馈，不直接改写规范 |

角色名称代表分工，不代表另起了新的进程。不同责任角色不得同时修改同一文件。

## 3. 阅读顺序

开始任何工作前依次阅读：

1. 项目根目录 `README.md`：协作入口。
2. 项目根目录 `团队协作与分工说明.md`：任务、交接和验收流程。
3. 项目根目录 `文件归属与责任矩阵.md`：当前唯一负责人和修改边界。
4. `../README.md` 和 `README.md`：数据区及规范区工作入口。
5. `task_rule.md`：采集、清洗、标注和交付流程。
6. `constraint.md`：输出、价格、图片、话术与发布约束。
7. `acceptance.md`：本次交付必须通过的验收项。
8. `../docs/issue_record.md`：当前未解决缺口，避免误报完成。

## 4. 强制规则

### 4.1 来源

- 每条关键事实保留来源库、具体条目、内容指纹，以及适用的 URL、抓取时间和型号/SKU（如有）。
- 两个本地知识库冲突时，采用更新、更全且能交叉核验的口径，并记录采用原因。
- 无法确认的内容标记「待核实」，不得补写。

### 4.2 价格

- 区分公开参考价、历史快照价、搭配价、起售价、补贴估算和可成交报价。
- 正式报价缺少精确 SKU、配置、数量、地区、有效期或询价依据时必须为空。
- 四级价格是待确认的假设模型，演示金额不是华为政策或正式报价。

### 4.3 客户与样例

- 客户画像区分明确输入、推断和待确认，不默认预算、身份或采购权限。
- 所有测试客户和对话显著标注为合成；不得加入真实客户隐私。
- 测试通过不证明真实咨询量、转化率或销售效果。

### 4.4 图片与 IMA

- 候选图不等于正式配图；未经画面、型号、SKU 和版权核验时保持 `model_verified=false`。
- IMA OpenAPI 已接入并完成只读检索验证；使用真实请求 ID、知识库 ID 和媒体 ID，不得编造来源。写入、导入和全量正文读取需单独验证。

### 4.5 发布与安全

- 不保存或提交原始知识库 ZIP、客户数据、Cookie、令牌、密钥、运行日志、模型权重。
- 不把本地运行、Git 提交、部署和外网可用混为一谈。
- 未得到明确授权，不执行 Git 提交、推送、部署或删除历史资产。

## 5. 状态口径

数据和交付物只使用以下状态：

- `draft`：已整理，未完成来源或质量复核。
- `verified`：通过本区验收，证据可追溯。
- `pending_external`：缺少真实政策、许可、客户验证或赛事认可，不能由内部推定关闭。
- `rejected`：存在事实、来源、格式或路径问题，退回责任角色修复。

`pending_external` 不等于失败，也不等于完成。问题记录必须写清还缺什么。

## 6. 交付与复核

- 每次交付附：改动范围、数据计数、来源清单、验证命令、通过项、未通过项、待核实项。
- 先自查 `acceptance.md`，再由 A 执行 Agent/自动化验收、E 协助全流程核对；不通过时由原责任角色修复。
- 通过后更新 `docs/变更日志.md`；长期缺口或阻塞更新 `docs/issue_record.md`。
- 禁止用修改评分、删除失败条目或放宽验收条件来制造通过。

## 7. 冲突处理

- 路径、字段或状态定义冲突时，以运行区公共契约和主工作区最新明确指令为准。
- 数据真实性冲突无法内部解决时标记 `pending_external`，保留双方证据，不擅自选择更有利的数据。
- 任何无法保持区域独立的文件先停止复制，在交付说明中列为「待决策」，不静默放错。
