# Agent 规范工作区说明

## 负责人

| 文件 | 主负责人 | 复核角色 | 职责 |
| --- | --- | --- | --- |
| `AGENTS.md` | A | E | Agent 和数据区总边界、状态和交付规则 |
| `task_rule.md` | A | D、E | 采集、清洗、标注、Agent 任务和交付流程 |
| `constraint.md` | A | D、E | 输出、销售话术、价格、图片和真实性约束 |
| `acceptance.md` | A | E | Agent、数据和交付验收清单 |

A Agent 核心工程师负责维护 Agent 运行规范；D 核对数据和检索可执行性；E 核对赛事需求、产品说明和提交材料。

## 开始工作前

1. 阅读项目根目录 `README.md`、`团队协作与分工说明.md` 和 `文件归属与责任矩阵.md`。
2. 阅读数据区 `../README.md` 和本文件。
3. 依次阅读 `AGENTS.md`、`task_rule.md`、`constraint.md` 和 `acceptance.md`。

## 修改规则

- 规范只能描述已验证事实、明确假设和待核实项。
- 不把合成样例、规则或占位能力写成真实模型效果。
- 不放宽价格、图片、客户画像和发布边界来让候选通过。
- A 统一修改规范；D、E 提交数据和产品侧的变更需求、证据与复核意见。
- 职责或目录变化时，同步更新根《文件归属与责任矩阵》。

## 交接

交付时说明修改目标、受影响任务、与运行区契约的对应关系、验收方法和未解决缺口。涉及事实或政策条件时保留来源和适用范围。
