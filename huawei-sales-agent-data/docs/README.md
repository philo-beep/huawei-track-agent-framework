# 项目文档工作区说明

## 负责人

E 产品与答辩工程师为文档主负责人；A 提供 Agent 实现、联调和验收事实，D 提供数据来源和质量证据，B/C 提供接口和前端体验事实。

## 文件职责

| 文件 | 主负责人 | 内容 |
| --- | --- | --- |
| `赛事需求文档.md` | E | 赛事目标、规则、范围、需求映射和限制 |
| `issue_record.md` | E | 未解决问题、责任人、状态和外部依赖 |
| `变更日志.md` | E | 结构调整、功能和验证记录 |
| `画像调研对比-20261022.md` | E | 客户画像询问方式修正、GitHub 成熟方案对比及待确认优化项 |

## 开始工作前

1. 阅读项目根目录协作入口和分工说明。
2. 阅读 `../README.md` 和 `../agent_spec/README.md`。
3. 运行区功能变化时阅读 `../../huawei-sales-agent/README.md` 和实际测试结论。

## 写作规则

- 只写已验证功能，未来能力明确标为计划或待验证。
- 不把本地测试写成公网已发布，不把合成金额写成正式报价。
- 未取得真实政策、图片许可、客户验证或赛事认可时保留待核实状态。
- 问题记录必须写清缺少什么、由谁负责、何时复核。
- 变更日志记录日期、改动、验证方式和遗留风险。

## 交接

E 确认文档与实际实现一致后提交；涉及数据事实时由 D 提供来源，涉及 Agent/接口/前端实现时由 A/B/C提供对应证据，A 和 E 共同完成验收记录。
