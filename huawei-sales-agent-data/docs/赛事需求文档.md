# 赛事需求文档

## 1. 项目定位

项目名称：**华销智策 —— 针对华为的销售智能体**。

目标用户：华为销售顾问。产品把一次客户推进拆成四步闭环：

1. 读懂客户：识别客户身份、行业、需求、预算、决策链、购买阶段和可触达渠道，明确输入、推断与待确认项。
2. 写出内容：结合客户画像和平台差异，生成能引导咨询的内容准备稿，并为产品事实保留来源。
3. 给出方案：按四级规则演算价格，输出报价边界和 0–30 分钟可执行的演示计划。
4. 推成交：输出有负责人、触发条件、依赖项和人工确认边界的下一步动作。

## 2. 两个核心痛点

| 痛点 | 赛事要求 | 当前交付口径 |
| --- | --- | --- |
| A 内容难以带来咨询 | 内容要贴客户、贴平台，并能引导下一步咨询 | 已有规则准备稿和平台结构建议；真实平台算法与咨询转化未验证 |
| B 半小时方案难交付 | 四级价格组合复杂，要求算得准、报得出、演得完 | 有四步价格演算和 4 段时间计划；四级政策是待确认假设模型，正式报价为空 |

## 3. 四步与交付物映射

| 闭环 | 关键输入 | 关键输出 | 验收重点 |
| --- | --- | --- | --- |
| 读懂客户 | 客户原话、行业、规模、预算、已有产品、接触场景 | 11 维画像、澄清问题、购买阶段 | 不编造缺失信息，能支撑后续内容与报价 |
| 写出内容 | 画像、产品事实、平台、目标动作 | 内容准备稿、事实引用、行动号召 | 来源可追溯，不承诺效果，平台结构有差异 |
| 给出方案 | 产品、配置、数量、预算、场景 | 四级演算轨迹、金额边界、30 分钟演示计划 | 金额计算一致，假设显式，正式报价边界清楚 |
| 推成交 | 画像、内容、方案、客户阶段 | 下一步动作、负责人、触发条件、依赖 | 动作可执行，涉及人工确认的节点不越权 |

## 4. 数据要求

- 主要本地数据源：任德耀新建华为 PC 知识库。
- 原华为 PC 知识库保留为去重别名，不作为独立佐证。
- 产品参数、配置和价格优先华为官网 / 华为商城公开页面。
- 每条关键事实保留来源、条目、URL、抓取时间、内容指纹和适用范围。
- 信息冲突时采用更新、更全面且可交叉核验的口径，并记录采用原因。
- IMA OpenAPI 已按用户授权接入，并完成只读知识库列表与知识检索调用验证；来源保留请求 ID、知识库 ID、媒体 ID。写入、导入和全量正文读取能力未在本轮声称完成。

## 5. 工程目标与真实状态

- 工程目标：四步闭环可运行、可演示、来源边界不丢失；用户提出过「规则自评 ≥ 60」的工程目标。
- 60 分是项目内部工程目标，不是赛事官方晋级线；是否通过初赛由评审决定。
- 已实现：本地网页交互、11 个合成样例、四步规则引擎、来源展示、JSON / Markdown 导出、禁用文件上传。
- 未完成：真实价格政策、当前可成交报价、完整 SKU、正式图片核验、真实平台转化、IMA 写入/导入与全量正文读取、30 分钟现场验证。
- 当前支持按请求启用 DeepSeek v4.1-flash 云端推理、IMA OpenAPI 检索和联网公开网页抓取；三项能力均已在本地完成真实调用验证。公开部署仍需单独注入凭据并验证网络与调用链。

## 6. 提交与发布边界

- 运行代码、数据区、产品说明书和部署链接分别验收，不以临时预览或历史截图代替真实访问。
- 公开发布前必须执行凭据、隐私、知识库、日志和模型权重白名单检查。
- 任何本地改动、Git 提交、推送、部署和公网验证都需要分别记录实际状态。
