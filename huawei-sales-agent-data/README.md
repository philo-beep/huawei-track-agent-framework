# 华销智策数据与 Agent 规范区

本目录是「华销智策 —— 针对华为的销售智能体」的并行数据区，用于保存数据集、测试样例、Agent 运行规范和项目文档。它不承载网页实现、业务运行代码、服务脚本或模型权重。

## 目录

```text
huawei-sales-agent-data/
├── datasets/
│   ├── README.md             # 数据集工作入口、来源和质量规则
│   ├── raw/                 # 原始证据、官网快照、候选图附件与采集清单
│   ├── cleaned/             # 清洗后的本地知识索引
│   └── test_sample/         # 合成测试样例与示例输出
├── agent_spec/
│   ├── README.md            # 规范区工作入口和责任表
│   ├── AGENTS.md            # 数据区协作规则
│   ├── task_rule.md         # 采集、清洗、标注和交付任务规范
│   ├── constraint.md        # 输出约束、销售话术规范和禁止话术
│   └── acceptance.md        # 数据与交付验收清单
├── docs/
│   ├── README.md            # 文档区工作入口和责任表
│   ├── 赛事需求文档.md
│   ├── issue_record.md
│   └── 变更日志.md
└── README.md
```

## 协作角色

| 角色 | 在数据区的职责 |
| --- | --- |
| A Agent 核心工程师 | 维护 `agent_spec/`，定义 Agent 运行规则、检索规范、验收标准和消费方式 |
| B 后端接口工程师 | 只读审核数据入库、字段和接口契约，不在数据区维护业务代码 |
| C 前端开发工程师 | 只读使用合成样例和产品展示数据，不直接修改原始数据 |
| D 数据与知识库工程师 | 维护 `datasets/` 的采集、清洗、切片、去重、索引和测试样例 |
| E 产品与答辩工程师 | 维护 `docs/`、`README.md`、issue、变更日志和赛事提交材料 |

## 当前数据基线

- 本地知识索引：130 条文档、112 条候选图记录、141 条价格记录。
- 官网清单：7 个采集目标，5 个成功、2 个失败；失败项保留空路径和空价格，不伪造成功。
- 候选图：112 个原始候选图记录均存在且全部保持 `model_verified=false`，正式可用产品配图数量为 0。
- 图文审稿图片：`cleaned/image_review_registry.json` 登记 4 张 HUAWEI MateBook 14（鸿蒙版）精确型号图片，均完成来源与辅助画面核验；`publication_ready=false`，等待人工终审与发布授权。
- 图文示例：`test_sample/content_draft.example.json` 和 `.md` 为合成客户样例，含图片来源清单、插入位置和事实来源索引。
- 运行样例：11 个合成样例，覆盖完整闭环、信息不足、模糊预算、比价、续约、兼容性、极端预算、政企流程、负面诱导和平台差异。
- 运行验证（2026-10-21）：Node 离线 16 项通过；Python 离线 5 项通过、2 项按环境跳过；图文本地 HTTP 链路 1 项通过（回环测试在沙箱外执行）。

## 数据边界

- 主要本地来源是「任德耀新建华为 PC 知识库」；原知识库只作为去重别名，不作为独立佐证。
- 产品参数和价格优先参考华为官网 / 华为商城快照，并保留页面 URL、抓取时间、内容指纹、适用型号或 SKU。
- 当前公开价格、完整 SKU、实时库存和可成交金额仍待核实；`actual_transaction_quote=false`。
- 四级价格是明确标注的可配置假设模型，不是华为真实价格政策，不能当作正式门店报价。
- 原始候选图未经完整画面、配色、SKU 与版权核验，不能作为正式配图；4 张精确型号审稿图片也只用于草稿，公开发布授权仍待确认。
- 咨询量、转化率和 30 分钟现场交付均没有真实业务证据，不得写成已验证。
- 不复制客户隐私、账号凭据、日志、原始 ZIP 或模型权重到可发布目录。

## 与运行区的关系

运行区位于 `../huawei-sales-agent/`。运行区只读取本目录中经过审查的知识索引、清单和候选图路径；本目录不反向保存运行区源码。接口字段以运行区 `backend/agent/contracts/` 和项目根目录《文件归属与责任矩阵》为准。

## 使用与核验

1. 修改数据前先阅读 `datasets/README.md` 和 `agent_spec/AGENTS.md`。
2. 按 `agent_spec/task_rule.md` 执行采集、清洗和来源标注。
3. 按 `agent_spec/constraint.md` 检查价格、图片、话术和真实性边界。
4. 按 `agent_spec/acceptance.md` 完成交付验收。
5. 产品与赛事文档按 `docs/README.md` 维护；已知缺口记录在 `docs/issue_record.md`，结构调整和验证结果写入 `docs/变更日志.md`。
