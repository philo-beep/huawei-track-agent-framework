# 五模块交接约定草案

版本：2026-10-20草案；主控建立，待B定版。当前没有改动原`contracts/marketing-*.schema.json`，本文件不冒充已生效的生产接口。

## 通用入口

每个模块在自己的`src/index.js`提供CommonJS导出`module.exports = { run }`，其中`run`是`async run(input, context)`。本轮只创建了目录，入口代码由各负责人按后续任务实现。

输入与返回采用普通JSON可序列化对象，不返回文件句柄、模型客户端、凭据、路径权限或跨模块可变对象。context由集成层注入只读资料查询、模型调用、时钟和取消信号等能力；不作为输出序列化。不依赖全局客户会话，换客户须使用新的request_id。

共同字段建议为`schema_version`、`request_id`、`module_id`、`status`、`data`和`issues`。状态采用`ready/needs_clarification/blocked/not_implemented`；`ready`只说明本模块输出可交接，不代表完整成稿或对外发布通过。问题标明`code/path/message/owner`，owner取M1—M5或主控，不用自然语言暗含状态。

## 模块间只传这些业务结果

| 生产方 | 数据 | 消费方 |
| --- | --- | --- |
| M1 | CustomerProfile：十一维画像、客户原话依据、待确认项、追问、冲突 | M2、M3、M5 |
| M2 | EvidenceBundle：fact_id、image_id、完整型号、原文、来源、时效、范围和许可状态 | M3、M4、M5 |
| M3 | ContentBrief：读者、问题、目标、切入点、卖点fact_ids及排序、结构、语气、配图image_ids、CTA目标 | M4、M5 |
| M4 | ArticleDraft：标题、导语、正文、CTA、标签、图片位置、句子与事实对应关系、修订摘要 | M5 |
| M5 | ReviewDecision：pass/needs_revision/blocked、逐项检查、责任模块、修复要求、交付结构 | 集成层与原责任模块 |

客户信息不因经过下游而升级为“已确认”。事实ID与图片ID必须能在当前证据包精确定位；模型不能新增ID、价格、许可或原文不存在的结论。表达可以自然改写，数字、适用配置与限制不能扩大。M5输出的问题由主控路由回原模块，不由M5覆盖上游输出。

M2允许直接用原始请求执行基础检索，因此可与M1独立开发；正式组合时再采用M1已确认条件细化。M3—M5可用明确合成的上游样例先开发，不等待其他模块上线；联调时必须替换为真实模块结果，Mock通过不算端到端验收。

## 定版与变更

B在`contracts/`维护正式Schema和版本，Mock在`mocks/`；需要变更时，模块在自己的`docs/`提出字段、原因、兼容影响和迁移方案。主控协调B、生产方和消费方共同确认，先合并兼容契约，再合并实现；破坏性变更升级版本，不静默覆盖。

稿件交付遵守手册四部分：场景判断、知识库依据、图文软文、核验结果。当前用户要求停用IMA，官网和本地替代源必须保留来源及赛事差异说明；不把假设政策、占位或无许可图片当成真实完成。
