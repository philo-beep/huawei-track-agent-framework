## 各板块的预定用途

| 目录 | 预定用途 |
| --- | --- |
| 00_主控协调 | 主 Agent 拆任务、安排依赖、协调跨板块问题。 |
| 01_客户理解 | 定义画像维度、输入依据和缺失追问，准备脱敏或合成交接样例。 |
| 02_资料与图片 | 设计按型号检索与来源记录方式，准备配图位置和使用条件说明。 |
| 03_内容策略 | 把客户需求转为文章切入点、卖点顺序、平台结构及写作任务书。 |
| 04_自然写作 | 设计正文生成和自然表达编辑方式，存放明确标注的合成稿件样例。 |
| 05_质检与交付 | 整理独立验收要求、问题归属及对外交付清单。 |
| 共享规范 | 放接口与交接格式的讨论草案，避免各模块自行定义不兼容字段。 |
| 集成与发布 | 预留联调、候选核对及实际发布记录位置。 |

## 与现有项目的关系

五个业务板块是工作划分，00及最后两个目录是配套协调区，不是额外业务板块。本目录不要求同时启动五个模型或五个进程。

现有 `backend/`、`frontend/`、`data/`、`contracts/`、`tests/` 和 `reviews/` 继续保留。新五模块代码在`modules/`实现，由主控协调原责任人在集成层适配现有应用；不在本中文工作区另复制运行代码或原始知识库。

`共享规范/接口草案/` 仅用于讨论，正式接口仍以 B 负责的 `contracts/` 为准；正式任务状态仍以 `python -m framework` 管理的 `.collaboration/state.json` 为准；真实验收仍由 QA 在 `reviews/` 留证。预览中的问题清单、候选及发布记录不能替代这些现有机制或 E 的实际发布确认。

根 `AGENTS.md`、运行器与消息Schema已增加M1—M5的独立目录边界。原A/B/C/D/E/QA继续负责公共支撑区域；M5只是核验功能开发者，不替代独立QA或E签字。

目录中只准备可共享的设计说明及合成样例；原始知识库、真实客户信息、密钥、模型权重和运行日志不复制到这里。IMA继续按当前用户指令停用，来源替代与手册要求的差异仍须保留说明。

这些空目录目前存在于本机文件系统；Git 不跟踪空目录。如后续确定需要同步目录，将为获确认的目录补充有实际内容的说明文件，再按项目原有审核和白名单流程提交。
