# 前端说明

## 负责人

C 前端开发工程师。

## 开始工作前

1. 阅读项目根目录 `README.md`、`团队协作与分工说明.md` 和 `文件归属与责任矩阵.md`。
2. 阅读运行区 `../README.md` 和本文件。
3. 接口字段或行为变化先与 B 确认；Agent 业务字段含义不明确时与 A 确认，数据和产品限制由 D、E 复核。

## 文件职责

- 入口：`index.html`，无构建步骤。
- 样式：`static/css/styles.css`，当前为白底、深灰文字、华为红点缀的商务销售工作台；使用 CSS 花瓣标识，不引入远程字体或第三方脚本。
- 交互：`static/js/app.js`，负责产品匹配输入、规范产品信息、逐条件覆盖、理由/限制/逐字引文展示、核心证据折叠、四步输入、运行轮询和 JSON/Markdown 导出。
- 页面顺序为“逐步客户画像 → 产品匹配 → 内容生成 → 报价方案 → 推进成交”；未知信息保持空白或“待确认”，不能自动补造预算、身份、采购权限、价格或兼容性。
- 不直接连接模型或外部服务，只调用同源 `/api/*`。

## 修改边界

- 只修改 `frontend/` 和分配给 C 的 `assets/` 中前端可见内容。
- 不复制后端规则，不猜测缺失客户信息，不隐藏限制和来源。
- 不引入未审查的第三方脚本、远程字体或追踪代码。
- 页面能力必须与实际 API 和当前规则模式一致。
- 当前使用原生 HTML/CSS/JavaScript；Vue、Tailwind 或流式渲染如后续引入，必须单独说明，不能写成已经完成。

## 验证与交接

- 在桌面和窄屏下检查产品匹配输入、系统/证据状态、逐条件覆盖、核心证据与折叠证据、四步带入、运行和导出入口。
- 运行 HTTP 冒烟，确认首页、CSS、JS 和 API 可访问。
- 交付附改动页面、交互路径、截图或可复现步骤、浏览器测试结果和已知限制。

## 逐步客户画像

- 首问由程序给出；用户填写已知背景后，调用 `/api/profile-steps` 由云端模型决定更合适的下一问。
- 每轮只渲染一个问题，快捷选项只填入回答框，不替客户提交；提交后轮询 `/api/runs/{id}`。
- 页面展示追问轮次、10 个维度覆盖、核心维度 6 项阈值和当前缺口；达到阈值或 8 轮上限后显示画像卡片。
- 画像字段必须保留原话依据；预算未定时不写入金额。完成后可一键带入产品匹配，未知字段保持空白。

## 产品匹配后的图文生成与强制核验

- 每个匹配候选提供内容生成按钮；页面选择公众号、小红书或朋友圈后调用 `/api/content-drafts`，由后端重新核验，不直接信任页面状态。
- 结果区先展示发布门禁结论、六项逐项核验和风险项清单，再展示原稿与审稿图片。
- 六项结果为“通过/不通过/降级”：不通过显示为阻塞；可剥离的图片授权或正文价格问题作为降级项，安全版本中不得再出现对应图片、标记或段落。
- 可发布安全版本单独展示，附带降级说明；原始稿、图片、来源清单、插入位置和完整 Markdown 仅用于审稿及下载。
- 图片通过同源 `/api/content-images/<sha256>` 展示；草稿固定提示公开发布授权和人工终审未完成。
